This records the acceptance run of the routing-catalog / `packet_request.json`
workflow added to `dev_tools/repo_context`, against this repository itself
(`python repo_context.py scan . --output /tmp/rc_real_out`, git revision
`7b658a3`, dirty worktree — this change set itself uncommitted).

## Scenario 1 — "Why is comparison_target absent from cross-segment outputs?"

- **Routing catalogs an LLM would inspect:** `routing/index.md` →
  `routing/tools.md` (covers `tools/compare_cross_segment.py` and
  `tools/run_segment_orchestrator.py`, both flat under `tools/`).
- **Request:** `/tmp/rc_e2e/scenario1.json` — symbols
  `build_comparison_registry_rows` (`tools/compare_cross_segment.py`) and
  `_clear_stale_name_all_before_run` (`tools/run_segment_orchestrator.py`),
  search term `comparison_target`.
- **First attempt narrowed the investigation on its own:** requesting the
  two *whole files* (5383 and 1867 lines) at the default 12000-token
  budget was correctly refused — `error: the requested explicit
  selector(s) do not fit within limits.max_estimated_tokens (12000)`,
  naming each oversized file. Per the contract, nothing was silently
  truncated; the request had to be revised to symbol-level selectors.
- **Final packet:** `packet_scenario1.md`, 26,415 chars (~6.4K est.
  tokens). Selector-resolution report: both symbols `resolved`. Found
  `comparison_target` is a `run_segment_orchestrator.py`/
  `generate_name_key_patterns.py` concept (a `--comparison-target`
  CLI flag gating name-projection stages) that `compare_cross_segment.py`
  itself never reads — consistent with `governance_relationships.py`'s
  documented gap in CLAUDE.md.
- **Provenance:** git revision + dirty flag, request-file SHA-256, tool
  version, per-item origin tags (`explicit_symbol_selector`,
  `exact_search_match`, `callee_expansion`, `import_expansion`).

## Scenario 2 — "Where is governance narrative tier assignment determined?"

- **Routing catalog:** `routing/tools.md` → `tools/generate_governance_narrative.py`
  (6890 lines; entry lists `assign_tier` among its top-level symbols with
  an exact line anchor).
- **Request:** symbol `assign_tier`, search term `tier`.
- **Result:** `packet_scenario2.md`, 16,184 chars. Resolved cleanly (only
  one `assign_tier` in the repo); returned the exact function body plus
  its statically-resolved callers/callees and internal imports.

## Scenario 3 — "Which code produces archetype classifications and which tests cover it?"

- **Routing catalog:** `routing/tools_archetype.md` →
  `tools/archetype/assign_archetype_classifications.py`.
- **Request:** symbols `_evaluate_signal` and `main` in that file.
- **Result:** `packet_scenario3.md`, 19,897 chars. Both resolved. No
  "Related tests" section was emitted for either symbol — a real,
  accurate finding: `tests/` has no file matching `*archetype*`, i.e.
  this classification path currently has no dedicated test coverage. The
  packet reports what's there rather than fabricating a test reference.

## Scenario 4 — large source file ("How is the sig_hash stage auto-inserted before discover/apply in run_extract_all.py's stage machine?")

- **Routing catalog:** `routing/tools.md` → `tools/run_extract_all.py`
  (1234 lines — the orchestrator `docs/extract_stage_matrix.md` documents).
- **Request:** symbols `_apply_sig_hash_to_phase0` and `_parse_stage_csv`,
  search term `sig_hash`.
- **Result:** `packet_scenario4.md`, 35,242 chars. Both resolved; this
  demonstrates targeting a specific mechanism inside a large file via
  routing-derived symbol names instead of dumping the whole 1234-line file.

## Scenario 5 — intentionally ambiguous symbol ("Show me the extract() function.")

- **Request:** unqualified symbol `extract` (every domain extractor
  defines one, per D-011's "one `extract(doc, ctx=None)` function" rule).
- **Result:** `packet_scenario5.md`, 1,757 chars. Resolution status:
  **ambiguous**, 16 candidates listed with exact
  `file:start_line-end_line` for each (`domains/arrowheads.py`,
  `domains/identity.py`, `domains/line_patterns.py`, ... 16 total). Zero
  source excerpts were emitted — the tool never guessed which `extract`
  was meant. Re-running with `{"name": "extract", "file":
  "domains/identity.py"}` (or a fully-qualified name) resolves it
  unambiguously.

## Could a user start from only the question?

Yes, for scenarios 2, 3, and 5 without any prior knowledge beyond what
`routing/index.md` → the matching `routing/<catalog>.md` surfaces (exact
symbol names and line numbers are printed there). Scenario 1 needed one
correction after the routing catalog's file-level pointers proved too
coarse for two very large files — the tool's own budget-conflict message
told the requester exactly what to narrow, without any manual reading of
source first. Scenario 4 is the same shape as scenario 1 but sized so the
symbol-level request succeeded on the first try. `discover` (the optional
lightweight command) was exercised separately and produces usable
channel-grouped candidates, though on a repository this large its generic
single-word channels (e.g. "segment", "cross") return dozens of
low-precision matches — expected given the no-scoring design constraint;
routing catalogs are the more precise entry point.

## Regression checks

- Full existing + new test suite: `pytest tests/ -q` → **122 passed**
  (74 pre-existing + 48 new), including the pre-existing
  `test_symlinks.py`, `test_large_file_cap.py`, `test_determinism_incremental.py`,
  and `test_validate.py` suites, unmodified.
- `validate` on the real-repo scan output: **PASS**, 0 errors, 0 warnings.
- Direct `--file`/`--symbol`/`--search`/`--line`/`--changed` packet paths:
  covered by the pre-existing `tests/test_packets.py` suite, still passing
  unmodified.
- Secret-redaction regression (`tests/test_safety.py`): a bounded fix
  (see rc_common.py's `_looks_secret_shaped`) stops the redaction regex
  from swallowing whole code statements that merely *mention* a word like
  "token"/"secret"/"password" without a plausible secret-shaped value
  (`token = user_provided_value_from_config` is now left untouched);
  genuinely secret-shaped lines (quoted literals, AKIA keys, PEM headers)
  are still redacted. Full elimination of every possible false positive
  (e.g. an unquoted identifier that happens to contain a digit, like
  `config_v2_token`) would need real entropy scoring or an allowlist —
  out of scope here; noted as deferred follow-up, not silently expanded.
