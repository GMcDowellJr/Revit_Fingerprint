# Canonical Name Identity Projection (PR1/PR2)

## What problem this stage solves

Every domain already computes a **configuration-based** `join_hash` (the `config`
projection) from its policy-selected identity items — the mechanism that drives today's
production pattern clustering (`Results_v21/analysis_v21/domain_patterns.csv`, built by
`tools/extractor.py`). That hash is authoritative for behavior, but it can't answer a
narrower, complementary question: *does this record's own name agree with the pattern its
configuration puts it in?* A record can be configuration-identical to a pattern while its
name drifts from that pattern's convention, or vice versa — and the config-based join_hash
alone can't surface that divergence.

This stage (PR1 + PR2) builds a second, independent projection — the **Canonical Name
Identity Projection**, keyed on `join_key_name_identity` — computed analysis-side, entirely
from already-exported `*.details.json` files, with no re-extraction through
`domains/*.py` + `runner/run_dynamo.py` required:

- **PR1** (`tools/apply_name_key_policy.py`, backed by `core/name_key_builder.py`)
  reconstructs `join_key_name_identity`/`join_hash` per record, for every domain that has an
  entry in `policies/domain_name_key_policies.json`. Domains are classified Native (the
  name value already lives in `identity_basis.items`), Widened (the name value is pulled
  from a phase2 bucket or raw `label.display`/`label.components` at the name-key call site
  only — not a subset of the identity items), or Excluded (no usable own-name evidence) —
  see `core/name_key_coverage.py`, the single source of truth for that classification.
- **PR2** (`tools/generate_name_key_patterns.py`, backed by `tools/pattern_id_utils.py`)
  clusters PR1's per-record output into patterns, parameterized by
  `--comparison-target {config, name, both}`: `config` republishes today's production
  `domain_patterns.csv` verbatim (byte-identical, never recomputed here); `name` clusters
  the name-identity projection's `join_hash` values into patterns, restricted to the 25
  Native+Widened eligible domains, tagging each pattern with its coverage class; `both` runs
  both and asserts their pattern IDs never collide (guaranteed by the pattern_id formula
  hashing in `join_key_schema`, which always differs between the two projections).

## Runbook invocation points

- **Run A-NameKey** — `tools/corpus_update_runbook.ps1` (l.120, `Invoke-Checked -StepName
  "Run A-NameKey: apply_name_key_policy.py"`) runs `apply_name_key_policy.py
  --export-dir ... --out $NAME_KEY_CSV` once per corpus, as an opt-in (`-NameKey`) step of
  Run A, right after flatten/apply/placeholders.
- **Run B-NameKey** — `tools/corpus_update_runbook.ps1` (l.163, `Invoke-Checked -StepName
  "Run B-NameKey: generate_name_key_patterns.py"`) runs
  `generate_name_key_patterns.py --comparison-target name --name-key-csv $NAME_KEY_CSV`
  as an opt-in step of Run B, explicitly marked "not required before Run C — Run C
  re-clusters per segment."
- **Per-segment orchestrator** — `tools/run_segment_orchestrator.py`'s Step 2b (l.1139+)
  re-invokes `generate_name_key_patterns.py --comparison-target name` per segment, first
  filtering the corpus-wide `name_key_results.csv` down to that segment's export files via
  `_filter_name_key_csv_to_segment()`, whenever `comparison_target` is `name` or `both`.

## `../../tools/pattern_id_utils.py`

### `stable_pattern_id(domain: str, join_key_schema: str, join_hash: str, taken: Set[str]) -> str` — [pattern_id_utils.py:L23](../../tools/pattern_id_utils.py#L23)

- **Reads:** `domain`, `join_key_schema`, `join_hash` -- caller-supplied strings, from build_clusters()'s per-group loop; `taken` -- a Set[str] threaded across every call within one build_clusters() run, mutated in place to dedupe pattern_ids batch-wide.
- **Calls:** hashlib.sha1(), base64.b32encode() (stdlib).
- **Thresholds:** `16` -- minimum base32 token length before the `pat_` prefix is accepted (hardcoded literal, per docs/PATTERN_ID_AND_LABEL_RULES.md's formula); `"pat_"` prefix literal.
- **Returns:** a `pat_<base32-lower-nopad>` string unique within `taken` (also mutates `taken` by adding the returned id); consumed by build_clusters() as each cluster's `pattern_id`. NOTE (mechanical-extraction risk): `taken` is caller-owned mutable state passed by reference and mutated as a side effect across repeated calls in one batch -- not a closure, but a naive per-function static parser reading only this function's own reads/returns would miss that its behavior depends on accumulated state from prior calls in the same build_clusters() invocation.
